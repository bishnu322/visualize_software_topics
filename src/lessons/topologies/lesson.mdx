A **topology** is the *shape* of a network: how devices and cables are arranged. The shape decides how much cable you need, what happens when something breaks, and how easily the network grows.

There are two views of topology:

- **Physical topology**: where the cables actually run.
- **Logical topology**: how data actually flows. For example, an old hub *looked* like a star but behaved logically like a bus, because every frame went to every port.

## Try it: break the network

Pick a topology, then **click a cable to cut it** and press **Send ping**. Watch whether the packet finds another way.

<Callout type="tip" title="Things to try">
- **Star**: cut one spoke. Only that PC is lost. Now imagine the *switch* dies…
- **Ring**: cut one link. The ping goes the long way round. Cut a second one and part of the ring is isolated.
- **Mesh**: cut several links. It still works, but count how many cables a 6-node mesh needs (15!).
- **Bus**: cut the backbone in the middle and half the network disappears.
</Callout>

## Comparing topologies

| Topology | Links for *n* devices | Single point of failure? | Typical use |
|---|---|---|---|
| Bus | 1 backbone | The backbone cable | Legacy coax Ethernet |
| Star | *n* | The central switch | Office/home LANs |
| Ring | *n* | Any link (single ring) | Metro fiber, Token Ring |
| Full mesh | *n(n−1)/2* | None | WAN core, critical links |
| Tree | *n−1* | Upper-tier devices | Campus networks |
| Hybrid | varies | depends | The real internet |

<Callout type="analogy">
A **star** is like a train station hub: every line goes through the center, so if the center closes, nobody gets anywhere. A **mesh** is like a city grid of streets: if one road is blocked, you take another.
</Callout>

<DeepDive title="Deep dive: real-world network design">

- **Three-tier campus design**: *Core* (fast backbone) → *Distribution* (policy, routing between VLANs) → *Access* (switches the users plug into). Small sites collapse core + distribution into a **collapsed core**.
- **Spine-leaf** (data centers): every leaf switch connects to every spine switch, so any server is always exactly 2 hops from any other. This is a partial mesh with predictable latency.
- **Redundancy needs loop prevention**: a physical loop of switches causes **broadcast storms**. **STP (802.1D)** / **RSTP (802.1w)** block redundant ports and unblock them if the active path fails.
- **Full mesh links** = n(n−1)/2. 10 sites → 45 links, 50 sites → 1,225 links. That's why WANs use **partial mesh** or **hub-and-spoke** (e.g. DMVPN).
- **WAN topologies**: point-to-point, hub-and-spoke, full/partial mesh; SD-WAN overlays build logical meshes over internet links.

</DeepDive>
