This is the classic interview question, and the perfect way to tie together everything you've learned. When you type `https://example.com` and press Enter, **dozens of protocols** cooperate in under a second.

<Journey3D />

## The big picture

1. **URL parsing**: the browser works out the scheme (`https` → port 443), host and path.
2. **ARP**: to send anything off the LAN, the laptop needs its **default gateway's MAC**. *(Lesson 4)*
3. **DNS**: turn `example.com` into an IP address. *(Lesson 7)*
4. **NAT**: the home router swaps your private IP for its public one. *(Lesson 3)*
5. **Routing**: every router forwards the packet hop by hop using longest prefix match. *(Lesson 5)*
6. **TCP handshake**: SYN, SYN-ACK, ACK opens a reliable connection. *(Lesson 6)*
7. **TLS handshake**: agree on encryption keys and verify the server's certificate.
8. **HTTP**: send the request, get the response.
9. **Render**: parse HTML, fetch CSS/JS/images, lay out and paint.

<Callout type="tip" title="Encapsulation at every hop">
At every router, the packet is **de-encapsulated up to Layer 3** (to read the IP), then **re-encapsulated** in a fresh Ethernet frame with new MAC addresses for the next link. The IP addresses stay the same end-to-end (except where NAT rewrites them). The MAC addresses change at every hop.
</Callout>

## What an HTTP exchange looks like

The request the browser sends (inside the encrypted TLS tunnel):

```http
GET / HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0 ...
Accept: text/html
Accept-Encoding: gzip, br
Connection: keep-alive
```

And the server's response:

```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
Content-Length: 1256
Cache-Control: max-age=604800

<!doctype html>
<html> ... </html>
```

**Status codes** tell you what happened: `2xx` success, `3xx` redirect, `4xx` client error (`404 Not Found`, `403 Forbidden`), `5xx` server error (`500`, `503`).

<Callout type="info" title="Where does the time go?">
Each **round trip (RTT)** between you and the server might take 20–100 ms. A fresh HTTPS page load costs about **1 RTT for DNS + 1 for TCP + 1 for TLS 1.3 + 1 for HTTP = 4 RTTs** before the first byte of HTML. That's why caching, CDNs (servers closer to you), connection reuse and HTTP/3 (which merges handshakes) matter so much.
</Callout>

<DeepDive title="Deep dive: the details interviewers love">

- **HSTS**: if the site is on the browser's HSTS list, `http://` is upgraded to `https://` *before* any request is sent.
- **DHCP** gave the laptop its IP, mask, default gateway and DNS server long before this (DORA: Discover, Offer, Request, Ack).
- **NAT/PAT**: the home router maps `192.168.1.10:52814 ↔ 203.0.113.7:61002` in its translation table so replies find their way back.
- **TLS 1.3**: ClientHello includes **SNI** and a key share (ECDHE); the server replies with its key share, certificate and Finished in one flight. Keys are derived with HKDF. **0-RTT resumption** is possible on reconnects.
- **Certificate validation**: chain to a trusted root CA, check the hostname (SAN), validity dates and revocation (OCSP stapling).
- **HTTP versions**: HTTP/1.1 (one request at a time per connection), HTTP/2 (multiplexed binary streams over one TCP connection), HTTP/3 (over QUIC/UDP, no TCP head-of-line blocking).
- **CDNs** use anycast and GeoDNS so `example.com` resolves to a server near you.
- **Browser rendering**: HTML → DOM, CSS → CSSOM, render tree → layout → paint → composite. `<script>` without `async/defer` blocks parsing.
- Try it yourself: `curl -v https://example.com` and your browser's DevTools **Network → Timing** tab show every phase.

</DeepDive>
