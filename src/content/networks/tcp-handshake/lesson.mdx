IP gets packets to the right **computer**. But a computer runs many programs at once: a browser, Spotify, a game. The **Transport layer (Layer 4)** delivers data to the right **program**, using **port numbers**.

- Web server: port **443** (HTTPS) / **80** (HTTP)
- DNS: port **53**
- SSH: port **22**
- Your side uses a random **ephemeral** port, e.g. 52814

A connection is identified by its **5-tuple**: source IP, source port, destination IP, destination port, protocol.

There are two main transport protocols, and they make opposite trade-offs.

## TCP: reliable and ordered

**TCP** (Transmission Control Protocol) guarantees every byte arrives, **in order**, with no duplicates. Before sending data, both sides set up a connection with the famous **3-way handshake**:

1. **SYN**: "Hi, I'd like to connect. My sequence number starts at *x*."
2. **SYN-ACK**: "OK! I got *x*. Mine starts at *y*."
3. **ACK**: "Got *y*. Let's go."

<TcpViz />

<Callout type="analogy">
A TCP handshake is like a phone call: "Hello, can you hear me?" "Yes, I can hear you, can you hear me?" "Yes!" Only now does the conversation start. **Sequence numbers** are like page numbers on a long letter sent in many envelopes: the receiver can put them in order and notice if one is missing.
</Callout>

## UDP: fast and simple

**UDP** (User Datagram Protocol) just sends. No handshake, no acknowledgements, no retransmission, no ordering. The header is only 8 bytes. If a packet is lost, it's gone, and that's often fine.

<TcpVsUdp />

| | TCP | UDP |
|---|---|---|
| Connection | Handshake first | None |
| Reliability | ACKs + retransmission | None |
| Ordering | Guaranteed | No |
| Flow/congestion control | Yes (windows) | No |
| Header | 20–60 bytes | 8 bytes |
| Used by | Web, email, SSH, file transfer | DNS, video calls, gaming, VoIP, DHCP |

<Callout type="info" title="What about QUIC / HTTP/3?">
**QUIC** runs over UDP but rebuilds reliability, ordering and encryption itself, combining the TCP and TLS handshakes into a single round trip. HTTP/3 uses QUIC.
</Callout>

- **Flow control**: the receiver advertises a **window**; the sender never has more than that many un-ACKed bytes in flight.
- **Congestion control**: the sender also keeps a **congestion window (cwnd)**. **Slow start** doubles cwnd every RTT; after loss it backs off (**AIMD**). Modern algorithms: **CUBIC** (Linux default), **BBR** (Google).
- **Retransmission**: on **RTO** timeout, or **fast retransmit** after 3 duplicate ACKs. **SACK** tells the sender exactly which blocks arrived.
- **RST**: immediately aborts a connection (e.g. connecting to a closed port).
- **States**: CLOSED, LISTEN, SYN-SENT, SYN-RECEIVED, ESTABLISHED, FIN-WAIT-1/2, CLOSE-WAIT, LAST-ACK, TIME-WAIT. Check yours with `netstat -an` or `ss -tan`.
- **SYN flood** attack: many half-open connections exhaust the server's memory. Mitigated with **SYN cookies**.
