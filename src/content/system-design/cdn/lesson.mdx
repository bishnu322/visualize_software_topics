No matter how fast your servers are, you can't beat the **speed of light**. A user in Sydney talking to a server in Virginia is ~16,000 km away; each round trip takes over 200 ms, and loading a page needs several round trips.

A **Content Delivery Network (CDN)** is a global network of caching servers, called **edge servers** or **PoPs** (points of presence), placed close to users. Static content (images, videos, CSS, JavaScript, even whole pages) is served from the nearest edge instead of the faraway **origin** server.

<Callout type="analogy">
Instead of every customer flying to the one factory to buy a product, the company stocks **local warehouses** in every city. The first order in a city ships from the factory and stocks the warehouse; every later order is delivered locally the same day.
</Callout>

## Try it

1. With **CDN: OFF**, load the page from every city. Far-away users suffer.
2. Turn **CDN: ON** and load again. The first load is a **MISS**: the edge fetches from the origin once.
3. Load **again**. Now every city gets a **HIT** from its local edge.

## What a CDN gives you

- **Lower latency**: content travels hundreds of km instead of thousands.
- **Less load on the origin**: the origin serves each file once per edge, not once per user.
- **Absorbs traffic spikes and DDoS attacks**: the CDN's huge capacity takes the hit.
- **TLS termination near the user**: handshakes complete faster.

| Content | Cache at edge? | Typical TTL |
|---|---|---|
| Images, video, fonts | Yes | Days–a year (use versioned filenames) |
| CSS / JS bundles | Yes | A year, with a hash in the filename (`app.3f9a.js`) |
| Public HTML pages | Often | Seconds–minutes |
| Personalised / logged-in API responses | Usually no | Not cached (or per-user at edge compute) |

<DeepDive title="Deep dive: push vs pull, invalidation and routing">

- **Pull CDN** (most common): the edge fetches from the origin on the first miss, as in the simulator. **Push CDN**: you upload content to the CDN ahead of time (good for large, rarely changing files).
- **Controlling caching**: the origin sends `Cache-Control: public, max-age=31536000, immutable` for versioned assets and `s-maxage` for shared caches. `ETag`/`Last-Modified` allow cheap revalidation (304 Not Modified).
- **Invalidation**: purge by URL or tag when content changes; or avoid purging entirely by changing the filename (cache busting).
- **How users reach the nearest edge**: **anycast** (the same IP is announced from every PoP and BGP routes to the closest) or **GeoDNS** (DNS answers with a nearby PoP's IP).
- **Origin shield**: a middle cache tier so 300 edges don't all miss to the origin at once.
- **Edge compute**: Cloudflare Workers, Lambda@Edge and Fastly Compute run code at the PoP for personalisation, A/B tests and auth.
- **Physics**: light in fiber travels at ~200,000 km/s, so 1,000 km ≈ 5 ms one way, ≈ 10 ms round trip before any routing overhead.

</DeepDive>
